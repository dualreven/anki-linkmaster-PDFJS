**规范名称**: 测试类型规范
**规范描述**: 定义测试的类型与适用场景，确保覆盖不同层次并提供快速回归能力。
**当前版本**: 1.1
**所属范畴**: 测试规范
**适用范围**: 所有 AI 进行的测试活动（UTF-8 与 `\n`）

**详细内容**:
- **冒烟测试（Smoke Test）: 新增于 v1.1**
  - 目标：在最短时间内验证系统关键面“能否启动/能否加载/关键契约是否存在”。用于每次改动后的快速兜底。
  - 特点：执行极快（建议 ≤ 60 秒）、依赖最少（可用 Mock/Stub）、覆盖面窄但指向关键路径。
  - 退出准则：
    - 构建/导入关键模块不报错；
    - 核心常量/事件/服务契约存在且非空；
    - 最小流程可被驱动（如路径解析、最小注册表可创建）。
  - 反模式（应避免）：
    - 引入真实网络/GUI/大体量构建导致耗时暴涨；
    - 与功能/集成测试目标混淆，加入过多断言；
    - 不稳定的环境依赖（时间/端口/并发）导致结果波动。
- **功能测试**: 验证单个功能点的正确性
- **集成测试**: 验证模块间交互的正确性
- **回归测试**: 验证修改未引入新问题，确保现有功能正常

**正向例子**:
```bash
# 冒烟测试：最小创建注册表与关键常量存在
runSmokeSuite()

# 功能测试：测试登录功能
testLoginFunction()

# 集成测试：测试用户模块与数据库交互
testUserIntegration()

# 回归测试：修改后测试所有相关功能
runRegressionTests()
```
