## 现状说明
- 合入阶段慢的主要原因之一是：回归测试过重/易超时/验证点不聚焦，导致“并行优势”被合入排雷抵消。

## 提出需求
- 将回归测试改造成“聚焦型”：只验证本次修复点，不引入大规模动态 import / 重依赖初始化。
- 给出一套“任务交付最小测试集”的规范：每个任务明确 `--runTestsByPath` 列表。

## 约束条件
- 仅允许改动测试与测试基础设施（优先在相关 feature 的 `__tests__` 内），不做业务功能扩展。
- 新增回归测试建议：单文件用时 < 3s（目标），并说明如何 mock 降耗。

## 可行验收标准
- `pnpm -s run lint` 通过
- 至少提交 1 条“加速/去 flake”的回归测试改造（包含前后耗时对比记录在 working-log）
